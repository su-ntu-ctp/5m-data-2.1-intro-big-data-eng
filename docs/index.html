Concept 3

The Data Engineering Lifecycle

Every data platform — FreshCart's included — moves data through the same core stages, with storage running underneath all of them.

Generation

Data is created at the source — a checkout event, a delivery scan, a scraped review. This lesson's Part 1 & 2 live here.

Ingestion

Moving data from where it's generated into the platform — covered from Unit 2.4 onward.

Transformation

Cleaning, validating, and reshaping raw data into something trustworthy — the direct fix for "nobody trusts the numbers."

Serving

Delivering trusted data to analytics, ML models, and dashboards — the payoff the rest of the module builds toward.

Undercurrents run through every stage: security, data management, DataOps, data architecture, orchestration, and software engineering. Storage — where MongoDB fits — is one of them, and it's what the rest of this unit gets hands-on with.

Concept 4

SQL vs NoSQL

FreshCart's orders already live in a relational (SQL) database — rows, columns, fixed schema. Not everything fits that shape. NoSQL databases trade some of SQL's structure and consistency guarantees for flexibility and horizontal scale, and come in four common flavours.

Simplest modelO(1) lookups

What it is: Every record is a unique key mapped to a value, like a giant dictionary. No querying by value — only by key.

Good for: Session tokens, shopping cart contents, real-time inventory counts looked up by product ID. Example: Redis.

Wide-columnAnalytics-friendly

What it is: Data is grouped and stored by column rather than by row, so scanning and aggregating one field across millions of records is fast.

Good for: Sales analytics rolled up across huge volumes — total revenue per SKU per day. Example: Apache HBase, Cassandra.

Relationships-firstTraversal queries

What it is: Data is stored as nodes and the edges connecting them, making "how are these two things related" a fast, native query.

Good for: "Customers who bought X also bought Y" recommendation engines. Example: Neo4j.

Flexible schemaThis lesson's tool

What it is: Each record is a self-contained JSON-like document — fields can nest and vary between documents, no fixed schema required.

Good for: FreshCart's scraped customer reviews and product catalogues, where fields differ from item to item. Example: MongoDB.

Hands-on Tool

MongoDB & pymongo

MongoDB is a document-oriented NoSQL database — data is stored as JSON-like documents inside collections, the rough equivalent of tables. This lesson's notebook connects to a MongoDB Atlas cluster with pymongo and runs CRUD operations against a sample movies dataset.

Create

Insert new documents into a collection with insert_one() or insert_many().

Read

find_one() returns a single document; find() returns a cursor over all matches, filterable with query operators like $gt and $regex.

Update

update_one() / update_many() modify fields on documents that match a filter, without replacing the whole document.

Delete

delete_one() / delete_many() remove documents matching a filter.

Aggregation Pipelines

Beyond simple queries, MongoDB's aggregation pipeline chains stages like $lookup (join across collections), $limit, and $sort to reshape data — similar in spirit to a SQL JOIN ... ORDER BY ... LIMIT.

Common pitfall MongoDB does not guarantee document order unless you explicitly add a $sort stage. A pipeline that applies $limit right after $lookup, with no sort in between, can return a different set of documents on every run — because "natural" storage order isn't fixed. Always sort before you limit.
Recap

Key Takeaways

  • "Big data" is described by the 5 V's — Volume, Velocity, Variety, Veracity, Value — not size alone.
  • Data size units scale by 1,024: KB → MB → GB → TB → PB → EB.
  • The data engineering lifecycle runs Generation → Ingestion → Transformation → Serving, with Storage underneath and undercurrents (security, orchestration, DataOps...) throughout.
  • NoSQL databases trade SQL's fixed schema for flexibility: key-value, column-based, graph-based, and document-based are the four common types.
  • MongoDB is document-based; pymongo drives CRUD operations and aggregation pipelines against it.
  • Always add an explicit $sort before $limit in an aggregation — MongoDB does not guarantee document order otherwise.
